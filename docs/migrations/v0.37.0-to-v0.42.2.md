# 0.37.0에서 0.42.2로 이전

## 변경 사항

0.37.0을 기준으로 현재 PR 전체를 비교하면 접근 판정 HTTP 프로파일의 추가 제약으로 `breaking`이다. 0.x 정책의 minor 이상 승격 요건은 0.42.2가 충족한다. 이 문서는 중간 버전별 안내와 별개로 main에서 직접 이전하는 소비자를 위한 누적 안내다.

접근 판정의 변경은 [0.37.0 → 0.38.0 안내](v0.37.0-to-v0.38.0.md)가 정본이다. `AccessAuthorizationDecisionCreateResponse`에 필수 `tenant_ref`와 JSON 타입 정보가 추가됐다. 호출자는 검증된 세션에서 유도한 tenant를 응답으로 받으며, 요청에 tenant·권한을 직접 지정할 수 없다.

HTTP 프로파일은 current-session cookie 인증, `Idempotency-Key`·`X-Request-ID`·`X-Trace-ID`, 직접 schema 응답과 공통 error envelope, `no-store`·`no-cache`, 201 replay, 중복 헤더·redirect 거부를 명시한다. 식별자 UTF-8 160바이트, obligations 16개, 요청 8192바이트·응답 32768바이트 상한을 적용한다. 기존 프로파일을 가정한 소비자는 이 동작과 decoder를 함께 갱신해야 한다.

개인 scope 조회와 Orchid visitor access 변경 계약, 두블룬 검증·동의·제안 생성·승인 완료·상태 조회 DTO도 추가됐다. 두블룬 DTO 추가는 공개 route나 SDK 호출 생성, 서명·제출 권한을 활성화하지 않는다. 내부 구현과 로컬 검증 범위는 [워크플로 상태 문서](../contracts/doubloon-approval-workflow.md)를 따른다.

## 마이그레이션 순서와 종료 조건

1. Core 응답 projection과 소비자의 strict decoder를 새 schema에 맞춘다. subject·session·tenant를 현재 세션 증거와 비교하고, 누락된 tenant를 임의 보충하지 않는다.
2. 위 HTTP 인증·metadata·멱등 재응답·상한·cache·redirect 규칙을 호출자와 서버 양쪽에서 검증한다. 응답 필드 추가를 거부하는 구버전 소비자를 먼저 식별해 함께 전환한다.
3. 개인 scope·visitor access는 각 operation의 권한과 서버 유도 binding을 확인한다. 새 계약 파일이 존재한다는 이유만으로 제품 경로를 활성화하지 않는다.
4. 두블룬 내부 기능을 사용하는 경우 기존 confirm은 동의 전용으로 유지한다. 완료 결과 재응답은 과거 명령 결과이며 현재 효력은 status에서 확인한다. default-disabled와 `execution_authorized: false`를 유지한다.
5. 새 응답·오류와 재시도 동작을 모든 해당 소비자가 처리하고 별도 배포·승격 검증이 끝난 뒤에만 구버전 decoder 지원을 제거한다. 전환 실패 시 해당 기능을 비활성화하고 호환되는 서버·소비자 조합으로 되돌린다. 이 문서는 배포 또는 운영 활성화 증거가 아니다.
