# v0.52.0 → v0.53.0

## 계약 변경

OIDC refresh token opt-in 계약에 필수 field를 추가하고 세 계약의 `schema_version`을 올렸다. 0.52.0 YAML 생산자는 아래 field를 모두 추가해야 하며, 하나라도 빠지면 0.53.0 parser가 계약을 읽지 않는다.

- `oidc_client_registry` (`schema_version: 3`): `allowed_grant_type_sets`, `refresh_token_grant_policy`
- `oidc_product_session` (`schema_version: 2`): `token_endpoint_grant_types`, `required_refresh_token_exchange_bindings`, `initial_token_response_optional_fields`, `refresh_token_response_fields`, `refresh_token_lifetime_policy`, `refresh_token_consumer_policy`, `revocation_token_type_hints`, `introspection_token_type_hints`, `revocation_refresh_handle_policy`
- `oidc_provider_runtime` (`schema_version: 2`): `refresh_token_grant_type`, `refresh_token_ttl_max_seconds`, `refresh_token_client_grant_gate`, `refresh_token_storage_policy`, `refresh_token_rotation_policy`, `refresh_token_required_bindings`, `authorization_code_response_fields`, `authorization_code_optional_response_fields`, `refresh_token_response_fields`, `refresh_token_denial_reasons`, `revocation_token_type_hints`, `introspection_token_type_hints`, `revocation_refresh_handle_policy`

`allowed_grant_type_sets`는 `authorization_code_only`와 `refresh_token_opt_in` 두 set만 둔다. 기존 client entry는 `allowed_grant_types`에 `authorization_code`만 유지하며, `refresh_token`을 명시한 client만 opt-in이다. access/ID token은 5분이고 refresh token은 매 성공마다 회전하며 최대 12시간이다. 초기 code 교환의 `refresh_token`·`refresh_expires_in`은 optional이고 refresh 응답에는 둘 다 필수다. 회전·폐기는 만료 전 활성·회전된 hash를 조회해 underlying Core SSO session을 revoke하는 정책으로 고정한다.

## 소비자 전환

0.52.0 형식 YAML을 생산하는 Core·문서·fixture는 세 계약의 `schema_version`과 위 필수 field를 함께 갱신한다. 0.52.0 baseline을 0.53.0 parser로 읽히게 만들거나 필수 검사를 optional로 낮추지 않는다. 호환성 검사는 0.52.0과 0.53.0을 별도 version으로 비교한다.

Core migration 79와 server BFF의 refresh 처리는 별도 opt-in이다. Core migration 79가 registry/provider field를 반영하고, server BFF는 `ACCOUNT_SESSION_REFRESH_ENABLED=true`, 중앙 session flag, 검토된 registry·discovery의 `refresh_token` grant가 모두 있을 때만 refresh를 요청한다. 기존 client는 `authorization_code`만 유지하며, 이 계약 변경만으로 client·user를 활성화하지 않는다. 사용자 활성화, Core/Edge/BFF 배포, npm publish는 이 문서의 범위가 아니며 npm release는 main의 별도 절차다.
