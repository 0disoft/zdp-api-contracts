# 0.37.0 → 0.38.0 접근 판정 tenant binding

## 변경 내용

HTTP 프로파일의 새 제약 때문에 최종 호환성 등급은 `breaking`이다. 0.x 정책에 따라 0.38.0 minor 승격과 이 마이그레이션 문서를 함께 적용한다.

`AccessAuthorizationDecisionCreateResponse`와 접근 판정의 필수 응답 binding에 `tenant_ref`가 추가된다. 검증된 현재 세션의 tenant를 나타내며 판정 대상 `scope_ref`와 구분한다. 요청에는 계속 tenant 권한 필드를 허용하지 않는다. 계약의 `contract-only` 상태, 201 allow/deny 결과와 runtime 승격 조건은 유지한다.

요청·응답의 JSON 타입도 명시된다. `decision`과 두 scope 필드는 닫힌 enum, 시각은 date-time 문자열, obligations는 문자열 배열이다. 필드 누락·null·알 수 없는 필드나 내부 persistence record를 성공 본문으로 보내지 않는다. SDK 생성 입력과 strict response decoder가 기존의 미타입 필드를 가정하지 않는지 함께 확인한다.

## 소비자 적용 순서

HTTP 프로파일도 확인한다. 기존 current-session cookie 설정을 공유하고 metadata header를 정확히 한 번 전달한다. 성공·오류 응답의 correlation과 cache 정책, body byte 제한, redirect 거부 및 201 replay를 구현한다. 오래된 계약은 호환성 비교용으로 로드할 수 있지만 HTTP 프로파일이 없으면 현재 계약 검증을 통과하지 못한다.

Core가 검증된 세션에서 tenant를 얻어 응답하도록 정확한 HTTP projection을 먼저 확정한다. 소비자는 새 schema를 반영하고 subject·session·tenant가 이미 확인한 세션 증거와 일치하는지 검사한다. 응답의 알 수 없는 필드를 거부하는 기존 소비자는 새 필드를 인식하도록 함께 갱신해야 한다. tenant 누락 응답을 임의로 보충하거나 제품 UUID에서 Core 참조를 추정하지 않는다. 그 후 별도의 Core 및 제품 승격 증거를 갖춰 연결한다.
